# R019-tool-loop-guard: R017 with the tool budget guarded against the waste the traces show (pre-registered)

**Hypothesis (one change, prompt-level, four parts that remove the same waste).** Preventing invalid scratch-file
operations and repeated empty-patch submissions reclaims the hard-limited 28-call budget for useful edits and
final-patch verification, and so increases the number of correctly resolved tasks.

**Baseline preserved: R017** (`experiment/r017-budget-fit`; source `7c22d5e`, results `4d058a7`, archive
`51a6ef8979e03fed1e77a9148436a8be5c6a57ccd18c61eec924068985576e60`, local 13/24; public 0.17 reported for submission
57116900, whose uploaded file hash Kaggle does not expose, so the archive ↔ submission association is inferred, not
verified; docs/r018.md §1). R018 (14/24) is a diagnostic control, not an improvement: the unchanged R017 archive rerun
in the same kernel also scored 14/24, and R018 vs that rerun was W3 L3 T18. R018 removed scratch files from patches
but did not show a resolution gain. R017 and R018 branches, archives and result directories are untouched.

Branch `experiment/r019-tool-loop-guard` starts from the R018 results commit so every artifact stays in history, and
restores R017's agent bytes: `agent.yaml` (9 tools + code-edit; only the leading comment differs), `configs/sampling.yaml`,
`eval_config.yaml`, `skills/code-edit/**` are R017's. Only `prompts/system.md` changes.

## 1. Tool contract, read from the harness source (swegemma 0.2.11, adk-submission 0.2.13; same wheelhouse as R018)

| fact | source | consequence |
|---|---|---|
| `write_file` / `read_file` / `edit_file` resolve paths with `_resolve_workspace_path`; any absolute path outside `/workspace` and any `..` raise `Path traversal detected: '<p>' escapes workspace root.` | `swegemma/tools/workspace.py` | `write_file("/tmp/repro.py")` can never work |
| `budget_gated` calls `ctx.check_budget()` (increments the count) **before** the tool body runs | `swegemma/tools/base.py` | a rejected `/tmp` write costs one of the 28 calls |
| `run_command` runs in the sandbox; the subprocess sandbox rewrites `/tmp` and `/workspace` in the command text to the task's own directories | `swegemma/sandbox/subprocess.py` `exec()` | the supported scratch route is a `run_command` heredoc into `/tmp` (every such call in the R018 traces succeeded) |
| `.git/info/exclude` gets `__pycache__/ *.pyc .pytest_cache/ *.egg-info/ build/ dist/ .coverage .adk_exec_*.py`, nothing else | `swegemma/harness/container_setup.py` `setup_git_exclude` | a scratch file anywhere in `/workspace` enters the diff (`submit_patch` runs `git add -N .`) |
| `submit_patch` is `budget_gated(count_tool_call=False)`: uncounted, allowed after the cap | `swegemma/tools/execution.py` | a model that loops on `submit_patch` is never refused |
| the loop ends on: patch submitted **and** a final text response with no tool call; or time; or `tool_calls_used >= max_tool_calls` (checked between runner turns); or `max_turns` (80); or 3 nudges | `swegemma/harness/agent_runner.py` | the stop action is "one sentence, no tool call" |
| `before_tool_callbacks` in the sandboxed YAML schema resolve from a `callback_registry`; `agent_runner` calls `compile_submission` without one, and `resolve_callback_fields` returns nothing when it is None | `adk_submission/schema.py`, `resolvers/callbacks.py`, `agent_runner.py` | **no submission-side wrapper or preflight can intercept `submit_patch`**; skills are counted tools the model has to choose to call |

So part B's protection is **prompt-level**. The structural bounds are the harness's own (`max_turns: 80`, 3 nudges),
and `eval_config.yaml` is kept byte-identical to R017 rather than lowering `max_turns` (R017/R018 legitimate sessions
used up to 38 LLM calls; the 80-turn end only ever hit the looping task).

Our local re-implementation (`src/g4agent/harness/tools.py`) now rejects out-of-workspace paths with the same message
(it used to map `/tmp/x` into the workspace) and applies the same git exclude, so the scripted tests reproduce the
real failure shapes.

## 2. Evidence from the R017 and R018 traces (`scripts/trace_mechanics.py`, python3 -I; numbers reproduce docs/r017.md, docs/r018.md)

| | R017 stored | R017 replicate (R018 kernel) | R018 |
|---|---|---|---|
| resolved / wrong fix / no edit | 13 / 5 / 6 | 14 / 6 / 4 | 14 / 5 / 5 |
| `write_file` of scratch files into `/workspace` (counted calls) | **44** | 32 | 0 |
| `rm` calls to clean them up (counted) | **10** | 12 | 0 |
| patches containing scratch files | 10 | 6 | 0 |
| `write_file` to `/tmp` rejected ("Path traversal"), each counted | 0 | 0 | **15 (14 tasks)** |
| calls refused with `BudgetExceeded` (the edit queued at call 29–30) | 5 | 1 | 4 |
| `edit_file` calls missing `old_string` (uncounted, but a turn each) | 21 | 6 | 15 |
| `submit_patch` calls / empty ones / max in one task | 27 / 1 / 3 | 31 / 1 / 2 | **71 / 51 / 49** |
| tasks hitting the 28-call cap / session timeouts / 80-turn end | 8 / 2 / 0 | 4 / 4 / 0 | 5 / 2 / 1 |
| a test or Python check after the final edit (edited tasks) | 15/18 | 18/20 | 17/19 |

Where the calls went in R017's six no-edit failures: all six received the harness `budget_warning` (attached once 10
calls remain, i.e. from call 18) and then made 6–10 more read/grep/run calls without editing (fastapi_14873 9,
fastapi_15589 7, rich_3063 8, rich_3105 10, rich_3180 6, rich_3470 8); three of them queued their first edit at call
29–30, which `BudgetExceeded` refused. Scratch handling cost R017 about 2 counted calls per task (`write_file repro.py`,
`python3 repro.py`, `rm repro.py`, often a second `submit_patch`), and R018's `/tmp` rule, written for `write_file`,
turned that into 15 rejected calls instead.

The empty-patch loop (R018 fastapi_14873): at 28/28 calls with no edit, the model called `submit_patch` (patch_size 0),
tried `edit_file` (BudgetExceeded), then called `submit_patch` 48 more times until the 80-turn limit, 83 s and 50 LLM
calls later. Its own prompt told it never to conclude without a non-empty patch; R017 carries the same rule.

Post-edit verification: R017 wrong fixes were mostly contract or cause errors a rerun of the agent's own test would
not catch (docs/r018.md §4), so R019 asks for one combined check, not a testing stage.

## 3. R019 implementation (prompt only; `prompts/system.md` = R017's prompt with four enumerated changes)

| part | R017 text | R019 text (summary) | mechanism |
|---|---|---|---|
| A. scratch files | no rule (scratch went into `/workspace` via `write_file`) | "Scratch scripts live in `/tmp` and are created with `run_command` only. Write and run in ONE call: `cat > /tmp/repro.py <<'EOF' … EOF` then `python3 /tmp/repro.py`. `write_file` to `/tmp/...` is rejected ("Path traversal detected") and still costs a tool call. Never create files inside `/workspace` that are not part of the fix." | prompt; the rejection itself is harness-structural |
| A'. fallback trigger (R018 finding kept) | fires on "old_string not found" twice | fires on the `mandatory input parameters are not present` error that actually occurs, or on two not-found failures; "do not resend it" | prompt; code-edit bytes unchanged |
| C. finish step | "Once your targeted test passes: submit immediately; verify patch_size > 0" | §4 "Finish": (1) ONE command = targeted check **and** `git status --short`; (2) one correction on an assertion failure, ignore unrelated breakage; (3) status must list only intended source files, one cleanup call (`rm`, `git checkout -- <path>`); (4) `submit_patch` once; `files_changed: 0` means nothing changed and resubmitting cannot change it: edit if calls remain, else one sentence and stop; (5) after a non-empty submit, one-line summary and stop | prompt |
| B. budget / stop rule | "Do NOT conclude without submitting a non-empty patch" | "Once a tool result carries `budget_warning` and you have not edited yet, your next call must be that edit"; "keep 3 calls in hand for the finish"; the anti-pattern now ends: once calls are gone, repeating `submit_patch` or re-sending a refused edit cannot create a patch — say what you would have changed and stop | prompt |

Unchanged from R017: model, 9 tools, `skills: [skills/code-edit]`, sampling (T 0.2, top_p 0.95, 8192 out, thinking
4096 with thoughts kept), budgets (240 s / 28 calls / 8 min / 80 turns), single agent, graph tools registered but
discouraged (R017 made 0 graph calls).

Archive (deterministic packager): `03cb3f91b5a69a3215fd487e0ebbbc15ecbca287579527ab080f0ad4069026c2`, 6 files.

## 6. Pre-registered promotion gate (recorded before the run; not to be revised after)
R019 passes only if **all** hold:
1. **≥ 15/24 resolved.**
2. **wins − losses ≥ 3** vs the same-run R017 control (paired per task).
3. **No material regression vs the stored R017** (13/24): resolved ≥ 13 and paired losses vs stored R017 ≤ 2.
4. **No unhandled tool-contract, sandbox or architecture failures:** 0 vLLM/sandbox/harness errors; no session ended
   by a tool-contract error; no unregistered-tool call.
5. **No empty-patch submission loop:** no task with more than 2 empty `submit_patch` calls, and no task ended by the
   80-turn limit.
6. **Materially fewer invalid tool operations and scratch artifacts** than both controls: rejected path operations
   (`Path traversal`) + `BudgetExceeded` refusals + workspace scratch `write_file` calls ≤ half of the same-run R017
   control's total, and patches with scratch files ≤ 2 (R017: 10, replicate: 6).
7. **Final-patch verification improves without a substantial increase in wrong fixes:** post-final-edit check coverage
   ≥ the same-run R017 control's fraction, and wrong fixes ≤ 6.
8. **Runtime:** projected full run ≤ 10.5 h.

14/24 or fewer is not a success, however clean or fast. If R019 fails, the evidence is documented and work stops
(no R020). The submission is not sent to the leaderboard automatically.
