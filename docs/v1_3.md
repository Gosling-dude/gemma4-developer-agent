| `edit.py`/`diagnose.py`: `/tmp/X` falls back to `$TMPDIR/X` | both scripts | E008/E009: the official **subprocess** sandbox rewrites `/tmp` in command text only; V1.2's `diagnose.py run /tmp/repro.py` fails there (E009). Scorer (Docker) unaffected | VERIFIED |
| Prompt: first edit by tool call 12; "what new information will this call give?"; no re-reading unchanged lines | `prompts/system.md` | 245/636 runs never edited (2 resolved); resolve rate peaks for first edits at calls 6–10 (65%) and falls after 15; failed runs read 11.5×/run vs 6.9× | 3P-DATA, confounded |

review.py (already covers the diff checklist; scratch files in patches don't hurt: 141/228 such runs resolved).

## 3. What was NOT measured
- **Any V1.3 (or V1.2 dev-set) resolution rate with the real model.** No GPU, endpoint or Kaggle credentials on
  this machine. Whether Gemma follows the two-step channel, gets line numbers right, and whether the extra call
  per edit costs more than it saves: TODO (R004).
- Graph-tool policies and `search_similar_code` modes were measured on localization (no model) and on real
  traces of *other* agents, not as end-to-end variants of ours.
- Dynamic stopping: measured on other agents' traces (0.28 calls after submit). Not re-measured for ours.
- Multi-agent ablation (section 12 of the brief): packaged, not run (R005).
- The failure taxonomy is of *other* agents on the *public dev set*; dev and LB correlate weakly (3P 744319).

## 4. Runtime projection (12-hour budget)
Worst case (every task hits the cap; 15 min server start, 0.15 min setup per task): **11.17 h for 116 tasks,
11.55 h for 120** (validator, VERIFIED arithmetic). V1.3 does not change the caps.

Expected case (ESTIMATE): E[T] = 15 min + N·(f·5.5 + (1 − f)·m + 0.15), thinking off at 3.5–5.6 s per call (3P).
With m = 3 min for tasks that finish: f = 0.2 → 7.3 h; f = 0.4 → 8.2 h; f = 0.6 → 9.2 h. The channel adds one
`run_command` per edit (≈ 5 s, 1–3 edits per task), i.e. ≤ 0.25 min per task, ≤ 0.5 h over 116 tasks in the
worst realistic case; it removes failed-edit retries (F002: 130 failed edit_file calls in 16 runs ≈ 8 per run).
The worst-case bound is unaffected because the time cap binds.
